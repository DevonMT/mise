# Mise

Offline-first grocery list at mise.devondoes.dev (React 19 + Vite + Dexie, installed as a PWA), with a small parse server in `server/`. Checks: `npx tsc -b`, `npm test`, `npx oxlint`, `npm run lint:css`, `npm run lint:ds`, then `npm run build`. The `src/ds/` files and `public/chrome.js` are generated by devondoes `ds/sync.mjs` (do not edit here).

## Gotchas

- 2026-10-29: the estate bar is bar v2 (#562): `EstateBar` (`src/EstateBar.tsx`) draws the markup at every width and `public/chrome.js` (synced, loaded in `index.html`'s head without defer) fills it in from `/api/me`. chrome.js looks for `.ds-bar` once at DOMContentLoaded and edits its nodes in place, so `main.tsx` renders `<EstateBar />` beside `<App />` (never inside it: App returns early on the loading and storage-locked screens) under `flushSync`, and the bar is `memo` with no props. It was desktop-only before; it now takes a row on a phone too.
- 2026-10-29: the theme is the estate's `ds_theme` cookie (`cookieThemeStore` in `src/ds/theme.ts`), set from the bar's control, which saves through `/api/estate/prefs` (the gateway's path, not Mise's). Settings has no Appearance section any more. `mise.theme` stays in `SYNCED_KEYS` and is only READ, once, as the migration source when there is no cookie (`main.tsx`); nothing writes it. The read is one-shot per device (`src/legacyTheme.ts`, flag `mise.themeMigrated`), so a stale copy never outvotes a later pick when the cookie lapses. A device whose cookie already exists (set by another app or the profile) keeps that cookie's theme and its old Mise pick is dropped: the estate pick wins. Don't remove the key until no installed device can still hold an unmigrated pick.
- 2026-10-29: Offline, the theme comes from the cookie (a year's Max-Age) via chrome.js in the head, which the service worker precaches (it is in `public/`, so the `*.js` glob takes it). The bar then shows the mark, place and theme button only (chrome.js's "unknown" state), and the hub emblems and avatar are simply absent (cross-origin, never cached).
- 2026-10-29: the SPA has no CSP of its own (the gateway adds none; only the public `/r` reader has one, and it loads no bar), so there is no `img-src` to loosen for the hub's emblems. If a CSP is added, `img-src` needs `https://devondoes.dev`.
- 2026-10-29: Title Case (#562): headings, buttons and tabs are Title Case; run devondoes `node ds/lint/check-title-case.mjs mise` (it reads the sibling checkout).
- 2026-10-29: `npm run lint:ds` and `ds/sync.mjs` resolve Mise as `../../mise` from the devondoes checkout they run from, so from a worktree of either repo they check or write the MAIN Mise checkout, not the worktree.
- 2026-10-30: `ListSwitcher` hooks must all sit above the `creating` early return (#675): opening the create sheet otherwise renders fewer hooks than the last render and React throws; oxlint's rules-of-hooks error also blocks the land gate.
- 2026-10-30: legacy duplicate lists ("My list"/"Pantry" made before 2026-09-30 with a random uid, beside the `default:` one) fold only inside `sync()`, after `applyRemote` (`src/fold.ts`, #680), never at mount. The old list is never deleted: it keeps a `foldedInto` marker, is renamed "... (moved)" (so older builds' dedupe skips it) and `applyRemote` refuses a tombstone for it; it is a hidden forwarding address and anything landing on it is moved on after each sync. Rows are only ever moved, never dropped. Anything that shows or picks lists must use `liveLists()` / `isLive` from `db.ts`; the hub's `captureTargets` skips it too (devondoes).
- 2026-10-30: a write that must keep its own `updatedAt` (and write its own tombstones) runs in `keepingStamps` (`sync.ts`); the fold stamps a moved row at its version + 1 so any real edit elsewhere still wins. `sync()` is single-flight (Settings' Sync Now and the auto-sync share one run). `dedupeDefaultLists` runs at mount only when sync is off.
- 2026-10-30: `.group` carries `min-width: 0` (#601): it is a grid item under `.groups`, and with the default `auto` one unbreakable name (a pasted URL) stretched every row past the column and pushed each quantity off a phone. Keep it when touching the aisle grid; `.name` clips with an ellipsis.
- 2026-10-30: ingredient matching (#702) is computed at read time in `src/match.ts` (`matchKey`, `itemKeys`, `sameIngredient`); stored `canonicalKey`s are never rewritten. `findMergeTarget` (`list.ts`) is the one place a merge is decided: exact key first, then the matcher on lists with aisles (grocery, pantry). Staples (`isStaple`) and `restockFromPurchase` use it too. "ground/powder" is stripped only from the dry-spice allow-list in `match.ts`, so chili powder, garlic powder and ground beef stay their own things; when adding an alias, add a "must stay apart" test beside it. A prep word that names a separate product ("sliced almonds", "shredded coconut", "fresh mozzarella", "diced tomatoes") is protected in `KEEP`, and a comma tail is a qualifier only when it is one short non-prep word (`tailQualifiers`), so a new prep word goes in `FILLER`.
- 2026-10-30: item rows (#705): `.row-main` wraps, `.row-name-wrap` asks for 14ch first and `.row-meta` (qty, price, due) drops under the name when it does not fit beside it; `.name` clamps at two lines, not one. The aisle columns are container-query driven and each must stay ≥ ~350px (3 columns from 1100, 4 from 1480, 5 from 1900 container width; see #707): more columns than that is what clipped names to four letters on a PC.
- 2026-10-30: Refine's size fit (#704) lives in `src/fit.ts` and compares ONE package (sizeAmount × sizeUnit, or a dozen/lb/each packaging) to the line's `quantity`/`unit`, read-time only, nothing stored. Only volume↔volume, weight↔weight, count↔count; a bare "oz" is weight, EXCEPT against a volume need on liquid packaging (carton, bottle, jug...) or a dairy/beverage product named milk/cream/juice/broth/stock (not sour cream, cream cheese, cans, tubs, bags), where it reads as fl oz and shows "≈". So cup vs a 16 oz salsa jar or 8 oz cheese bag shows nothing on purpose. Add new unit spellings to the `UNITS` table there, plus a test.
- 2026-10-30: recipe bulk-adds skip pantry stock (#703): `addRecipeToList` returns `{ added, skipped }`; a line is skipped when `getInStockKeys()` (`lists.ts`: live pantry lists, not `checked`, not `pending`) matches it via `itemKeys`. Never Add These staples are still skipped silently and first; only the pantry skips are reported (toast "Skipped N you have: ..." + "Add anyway" = `addSkipped`). `shopTheWeek` returns the same `skipped`. Capture's review pre-unchecks them with an "in pantry" tag, recipes only (a typed list is never second-guessed). A marked-out pantry item never skips anything.
- 2026-10-30: `.app` has no max-width at any width (#707): the cloth (`--bg` + gingham `::before`) is painted on it, so a cap stops the background partway across the screen and starts the gingham at .app's corner. Below 900px the content column is capped by `.app`'s `padding-inline` from `--col` (640px, 880px at 700-899) instead. Width is handled by the aisle columns (container query on `.scroll`: 3 from 1100, 4 from 1480, 5 from 1900, each ≥ ~355px); prose keeps its own caps (`.view` 720px, sheets, `.tabs`). Don't re-add a `.app` cap.
- 2026-10-30: "Never Add These" is gone from Settings (#688): it is an "Always on hand" toggle on a pantry item (`ItemSheet`, pantry lists only; `setAlwaysHave` in `lists.ts`) with a house marker on the row. `getStapleKeys` still reads `alwaysHave` (silent skip, even when marked out); an ordinary in-stock pantry item is the reported skip (#703). `src/alwaysHave.test.ts` pins the three.
- 2026-10-30: the store and area live in Refine (#712), not Settings: a chip at the top of `RefineSheet` opens `PlacePanel` (area = ZIP or town, store = typed or a fixed chain chip list). `mise.store` and `mise.area` are both in `SYNCED_KEYS`; Settings only shows them read-only under Store Prices. The first-open question is per device (`mise.refineAsked`, localStorage, deliberately not synced). Both go to the AI via `/api/refine` and `/api/prices` as `store` and `area`; the server cleans them (`cleanPlace`: one line, no control chars, 60 chars) and sends them as a JSON-quoted SHOPPER line in the user turn (`shopperLine`); the system prompts only point at it (`STORE_REF`), because they are user text and never go inside a system prompt, and a blank store with no area stays "a typical US grocery store".
- 2026-10-30: "Use My Location" is a tap, never automatic: `navigator.geolocation` runs in the browser and `nearestTown` (`src/cities.ts`, ~150 towns, approximate) turns it into "City, ST". Coordinates are never stored or sent; only that town name is kept, editable. The chain chips are a fixed list, not a store locator, so they are labelled as common stores, not "near you".
- 2026-10-30: aisles (#712): `setAisle` (`catalog.ts`) moves the list row AND the catalog entry; `applyRefinement` now writes `section` on an existing catalog entry too (it used to patch everything but the aisle, so a refined aisle reverted on the next add). The aisle-order editor is `AisleOrderSheet`, opened from the list menu ("Aisle Order") for lists that group by section; it edits the order for whichever store Refine last set.
- 2026-10-30: a fixed list uid must start with `default:` (#682). Every account seeds the same `default:list`/`default:pantry`, the wire names a list by uid alone, so the platform refuses to share a `default:` list (409, shown by `SharePeople`) and its table has a CHECK against it. A new fixed uid without the prefix would be shareable and file one person's items under another.
- 2026-10-30: a device refuses a list tombstone for any uid it has ever held folded (#684): `rememberFolded` keeps uid → target in localStorage `mise.sync.folded` (not a row), and `asForwarding` (fold.ts) puts the list back folded, renamed out of the app-made names. `applyRemote` also skips any tombstone the same state carries a NEWER record of (#685): the record is the agreed row, so the local row is neither restored with today's stamp nor deleted and re-added.
- 2026-10-30: local data is bound to an account (#278, `src/account.ts`): `mise.sync.account` in localStorage; every push sends `account`, the platform (devondoes `platform/src/mise.ts`) answers 409 before merging when it is not the signed-in user, and /state + /health answer with `account`. Sync then stops (`reason: 'account'`) and `AccountSheet` asks: Clear This Device (`clearThisDevice`, no tombstones, then reload) or Keep Them as Mine (`keepForAccount`). An unbound device (no `account` sent) binds to the first account it syncs as, unless its push carries a list/item/recipe uid that is another user's and not shared with the caller: the platform 409s that too. Keep binds only after its push succeeds. The inbox (`Handoffs`) waits for an ok sync. Clear drops every `SYNCED_KEYS` key plus the per-list ones (`DATA_KEYS`). Against a platform without the field nothing binds, so the platform must deploy first. Browser-test against a stub platform (a vite plugin that rewrites ENDPOINT), never the real one: localhost:5173 is on the real allow-list.

- 2026-11-04: every dialog is `<Sheet>` (backdrop, `useDialog` Esc/focus trap, drag); there is no `.scrim` class, and a raw `className="scrim"` renders unstyled inline (#715, SharePeople). Style a sheet's grid/layout on `.sheet-body`, never on `.sheet` (the flex column that lets the body scroll). `.hint-banner` is shared by the swipe hint, `.signin-banner` and `.account-banner`; the pointer media query hides only the swipe hint, so a banner that reports a state needs its class in the `display: flex` override beside it (#716).
- 2026-11-04: `npm run lint:ds` does not run from a worktree (`../devondoes` resolves under `.claude/worktrees`); skip it when `src/ds/` and `public/chrome.js` are untouched.
- 2026-11-04: server door rules live in `server/src/guard.ts` (pure, tested by `server/src/guard.test.ts`, which `npm test` runs): the AI daily cap is per user, keyed by lowercased email, under a `GLOBAL_DAILY_CAP` ceiling (default 5x) so forged identities cannot multiply it, and spent right before a model call (a bad request or dead link costs nothing); `/api/status` never counts and is not open to non-admins (gateway `X-Platform-Groups` must contain `admin`; it needs the gateway door, and the trailing-slash spelling gets the same gate). Model routes still need `X-Platform-Variant: full` until Mise moves to `X-Platform-Capabilities`. Errors to the phone are plain sentences (`brokerFailure`); the broker's detail goes only to the journal. Server changes need `npm run deploy:server`, not just the client deploy.
- 2026-11-04: recipes carry standard pack sizes and spice amounts (#774), reversing the 2026-08-11 "never invent a pack size" parse rule. `src/packSizes.ts` is the table (ordered, first match wins: put a specific spelling above a general one) and the fill-gaps-only merge; the table beats the model's estimate, never a stated size. Filled fields carry `sizeEstimated` / `amountEstimated` on the recipe line and show as "≈"; editing the amount in RecipeEditor clears `amountEstimated`. Recipes only: on a typed list `standardizeResult` nulls any value the model flagged as estimated (pack fields, qty/unit), not just the flag. Estimates are OPT-IN on `/api/parse` (`estimates: true`, sent by `parseCapture`): an older bundle saves the pack fields but not the flags, so it must never get estimated sizes. Table rules: rules match the name, then the key (`claims`); the exclusion (`not`, `NOT_A_SPICE`) always runs on the name, and on the key too when only the key matched ("jalapeño" keyed "jalapeno pepper"); produce and meat lines get a pack only when their unit names a container; a stated unit with no number is kept (`fitAmount`). Standardize (recipe detail) is the table alone without AI and asks `/api/standardize` only about lines with no amount or a container ("jar") with no size, never "2 onions", and never a line marked `estimateAsked`. It is set only on lines the server says the model saw (`asked` in the `/api/standardize` reply, at most 60 per call; `estimates: true` echoed by `/api/parse`), answered or not; renaming clears it. An estimated amount never goes onto a list row (`listAmount`), so it cannot split a merge; the pack does. The flags do not travel in share links or onto list rows yet (#778).
- 2026-11-08: moving items (#808) lives in `src/move.ts`: a move is an UPDATE of `listId`/`backlog` (same uid, fresh stamp from the hook, not `keepingStamps`: it is a real edit and must win), except a row whose ingredient is already on the destination, which merges via `findMergeTarget` + `mergeInto` (`list.ts`) and is deleted; Undo puts it back with its own uid. Sub-lists are `List.parentUid` (unindexed, syncs in the list body, one level deep: `subListParent` ignores a parent that is gone, hidden, another kind or itself a sub-list). Order lists for display with `listTree` (`db.ts`). The `mise-offline` launch entry in the parent folder runs the MAIN checkout; a worktree needs its own entry.
- 2026-11-08: the buy layer (#811) lives in `src/buy.ts` (pure) and `src/AddRecipeSheet.tsx`: Add to List opens a review that shows the recipe's words and the package to buy, picked from `soldSizes()` (packSizes `sold`, else `size` + `alt`) for the LEAST LEFT OVER, ties to fewer packages then the smaller one, one size per line. It buys for the top of a range (`RecipeIngredient.quantityMax`, share key `m`); a stated (not `sizeEstimated`) pack beats the table. Bridges between units: a liquid's bare oz is fl oz (`liquidProduct` in fit.ts), and `perCup` turns cups into weight; anything else falls to Refine, which now sends `quantity` so the model sizes counts (`refineLines`, server). "soup can" is a 10.5 fl oz measure unit; the Soup Can chip (`soupCanToggle`) rewrites a liquid counted in plain cans and the sheet saves it to the recipe. A `buyOnly` table rule (eggs, tortillas) is skipped by `lookupPack`, so Standardize never writes a carton onto "1 egg". `addRecipeToList` (meal plan Shop the Week) uses the same `buyLine`.
- 2026-11-08: Match My Names (#812) lives in `src/matchNames.ts` (logic) and `src/MatchNamesSheet.tsx` (the row under a recipe's ingredients + the approval-card `<Sheet>`). Not `MatchNames.tsx`: it collides with `matchNames.ts` on case (TS1261), like RecipesView. Sources are live pantry rows (marked-out included, pending not) then favorites. A card is "same" (`sameIngredient`) or "close": one key's words are the other's plus only words from the `DESCRIBES` allow-list ("original", "boneless", "condensed"...) or a `DESCRIBE_PAIRS` pair ("low sodium", "extra lean"; never a lone "low"/"extra"/"reduced"). "mix" is a different product ("rice mix", "cocoa mix") except after a `MIX_OK` word (seasoning, Bisquick, Jiffy). A card whose line was edited since the sheet opened is dropped and counted in the closing toast. Add a "must stay apart" test with any new describing word. An accepted card writes name, canonicalKey (the source's own) and aisle, clears `estimateAsked`, keeps amount and pack; `acceptCards` drops a card whose line changed since. Skip is not stored. No AI yet.
- 2026-11-08: a new service worker no longer reloads the page mid-task (#817): `main.tsx`'s `controllerchange` hands off to `reloadWhenIdle` (`src/update.ts`), which waits while `pageBusy` (any `useBackLayer` layer open, via `openLayers()` in back.ts, or a focused field) and reloads when that clears or the page is hidden. Testing in the browser pane: after an HMR edit, `import('/src/back.ts')` from the console gets a second module copy (Vite's `?t=`), so restart the preview server before reading `openLayers()`.
- 2026-11-08: Plain Name cards (#818): recipes say plain names, brands are Refine's (Devon's rule). `src/plainNames.ts` `plainName()` runs KEEP (household names that ARE the product: Velveeta, Cheez Whiz, Kraft Singles, Rotel, Cool Whip, Doritos...), then SWAPS (a brand standing for a type, narrowed to that product: Veg-All, Bisquick, Jiffy + corn, Crisco shortening; "franks" are not Frank's), then drops MAKERS in front of a plain product (Hormel, Campbell's, Jiffy peanut butter...) unless what is left dangles ("pace of life"); anything unlisted is left alone. `nameCards` puts a 'plain' card first, to his own pantry/favorite name for that plain product if he keeps one, and never offers a branded name of his as a target. A plain card keeps the line's canonicalKey when the key names no brand (it was broader). The parse prompt's PLAIN NAMES rule mirrors KEEP by hand: change both.
- 2026-11-08: `/api/refine` answers go through `alignRefine` (parseContract.ts, #820) before the client sees them: the client files options by its own canonicalKey, so an answer the model keyed by the NAME ("canned mixed vegetables") left every row "No options suggested". Order: exact key, then key or name loosely (case, punctuation, plural s), then position when the counts agree; each sent key once. A realignment logs `refine: N answer(s) realigned` to the journal. RefineView turns an answer that matches nothing on the list into an error, not empty rows.
- 2026-11-10: no ghost values in fields (#837). The one allowed `placeholder=` is the recipe search box (an action prompt); `src/ghostValues.test.ts` fails on any other. A hidden hint still keeps its line, so a hint-less field beside a hinted one leaves a short gap. Rule text: `~/.claude/core/writing-voice.md`.
