# Mise

Offline-first grocery list at mise.devondoes.dev (React 19 + Vite + Dexie, installed as a PWA), with a small parse server in `server/`. Checks: `npx tsc -b`, `npm test`, `npx oxlint`, `npm run lint:css`, `npm run lint:ds`, then `npm run build`. The `src/ds/` files and `public/chrome.js` are generated by devondoes `ds/sync.mjs` (do not edit here).

## Gotchas

- 2026-10-29: the estate bar is bar v2 (#562): `EstateBar` (`src/EstateBar.tsx`) draws the markup at every width and `public/chrome.js` (synced, loaded in `index.html`'s head without defer) fills it in from `/api/me`. chrome.js looks for `.ds-bar` once at DOMContentLoaded and edits its nodes in place, so `main.tsx` renders `<EstateBar />` beside `<App />` (never inside it: App returns early on the loading and storage-locked screens) under `flushSync`, and the bar is `memo` with no props. It was desktop-only before; it now takes a row on a phone too.
- 2026-10-29: the theme is the estate's `ds_theme` cookie (`cookieThemeStore` in `src/ds/theme.ts`), set from the bar's control, which saves through `/api/estate/prefs` (the gateway's path, not Mise's). Settings has no Appearance section any more. `mise.theme` stays in `SYNCED_KEYS` and is only READ, once, as the migration source when there is no cookie (`main.tsx`); nothing writes it. The read is one-shot per device (`src/legacyTheme.ts`, flag `mise.themeMigrated`), so a stale copy never outvotes a later pick when the cookie lapses. A device whose cookie already exists (set by another app or the profile) keeps that cookie's theme and its old Mise pick is dropped: the estate pick wins. Don't remove the key until no installed device can still hold an unmigrated pick.
- 2026-10-29: Offline, the theme comes from the cookie (a year's Max-Age) via chrome.js in the head, which the service worker precaches (it is in `public/`, so the `*.js` glob takes it). The bar then shows the mark, place and theme button only (chrome.js's "unknown" state), and the hub emblems and avatar are simply absent (cross-origin, never cached).
- 2026-10-29: the SPA has no CSP of its own (the gateway adds none; only the public `/r` reader has one, and it loads no bar), so there is no `img-src` to loosen for the hub's emblems. If a CSP is added, `img-src` needs `https://devondoes.dev`.
- 2026-10-29: Title Case (#562): headings, buttons and tabs are Title Case; run devondoes `node ds/lint/check-title-case.mjs mise` (it reads the sibling checkout).
- 2026-10-29: `npm run lint:ds` and `ds/sync.mjs` resolve Mise as `../../mise` from the devondoes checkout they run from, so from a worktree of either repo they check or write the MAIN Mise checkout, not the worktree.
- 2026-10-30: `ListSwitcher` hooks must all sit above the `creating` early return (#675): opening the create sheet otherwise renders fewer hooks than the last render and React throws; oxlint's rules-of-hooks error also blocks the land gate.
- 2026-10-30: legacy duplicate lists ("My list"/"Pantry" made before 2026-09-30 with a random uid, beside the `default:` one) fold only inside `sync()`, after `applyRemote` (`src/fold.ts`, #680), never at mount. The old list is never deleted: it keeps a `foldedInto` marker, is renamed "... (moved)" (so older builds' dedupe skips it) and `applyRemote` refuses a tombstone for it; it is a hidden forwarding address and anything landing on it is moved on after each sync. Rows are only ever moved, never dropped. Anything that shows or picks lists must use `liveLists()` / `isLive` from `db.ts`; the hub's `captureTargets` skips it too (devondoes).
- 2026-10-30: a write that must keep its own `updatedAt` (and write its own tombstones) runs in `keepingStamps` (`sync.ts`); the fold stamps a moved row at its version + 1 so any real edit elsewhere still wins. `sync()` is single-flight (Settings' Sync Now and the auto-sync share one run). `dedupeDefaultLists` runs at mount only when sync is off.
- 2026-10-30: `.group` carries `min-width: 0` (#601): it is a grid item under `.groups`, and with the default `auto` one unbreakable name (a pasted URL) stretched every row past the column and pushed each quantity off a phone. Keep it when touching the aisle grid; `.name` clips with an ellipsis.
- 2026-10-30: ingredient matching (#702) is computed at read time in `src/match.ts` (`matchKey`, `itemKeys`, `sameIngredient`); stored `canonicalKey`s are never rewritten. `findMergeTarget` (`list.ts`) is the one place a merge is decided: exact key first, then the matcher on lists with aisles (grocery, pantry). Staples (`isStaple`) and `restockFromPurchase` use it too. "ground/powder" is stripped only from the dry-spice allow-list in `match.ts`, so chili powder, garlic powder and ground beef stay their own things; when adding an alias, add a "must stay apart" test beside it.
